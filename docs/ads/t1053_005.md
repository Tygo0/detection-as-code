# ADS: Scheduled Task Creation (T1053.005)

Alerting & Detection Strategy (Palantir format).

## Goal
Detect an adversary creating a Windows scheduled task for execution or persistence.

## Categorization
- ATT&CK: T1053.005 - Scheduled Task/Job: Scheduled Task
- Tactics: Execution, Persistence

## Strategy abstract
Watch process-creation telemetry (Sysmon Event ID 1) for `schtasks.exe` invoked with
`/Create`. Scheduled task creation also surfaces as Security 4698 and Sysmon 1; this
rule uses the process-creation path, which is present whenever the CLI tool is used.

## Technical context
`schtasks.exe /Create` registers a task that the Task Scheduler later runs, optionally
as SYSTEM or at logon/boot - a common persistence and execution primitive. Verified with
Atomic Red Team "Scheduled task Local" (`42f53695-ad4a-4546-abb6-7d837f644a71`), which runs
`SCHTASKS /Create /SC ONCE /TN spawn /TR C:\windows\system32\cmd.exe /ST <time>`.

## Blind spots and assumptions
- Assumes Sysmon is installed with process-creation logging (sysmon-modular baseline).
- Task creation via the Task Scheduler COM API or PowerShell `Register-ScheduledTask`
  does not spawn `schtasks.exe` and is NOT caught by this rule (future rule).
- Does not inspect the task action, so it cannot judge whether the task itself is malicious.

## False positives
- Software installers and admin scripts routinely create scheduled tasks.
- Measured against the benign baseline recording. If the benign hit rate is non-zero,
  narrow by parent process or exclude known-good task names.

## Validation
- Fires on: `recordings/attack/T1053.005/42f53695-...evtx`
- Silent on: `recordings/benign/workstation-baseline.evtx`
- Enforced by `tests/test_detections.py` on every push.

## Response
Confirm the task name, trigger, and action (`schtasks /Query /TN <name> /V`). If
unexpected, capture the task action, who created it, and remove it.
