# ADS: Process Creation via WMI (T1047)

## Goal
Detect processes launched through WMI, a common execution and lateral-movement primitive.

## Categorization
- ATT&CK: T1047 - Windows Management Instrumentation
- Tactic: Execution

## Strategy abstract
Watch process-creation telemetry (Sysmon EID 1) for a script interpreter
(powershell/cmd/wscript/cscript/mshta/rundll32) whose parent is the WMI provider host
`WmiPrvSE.exe`. That parent-child pairing indicates creation via `Win32_Process.Create`.

## Technical context
WMI `Win32_Process.Create` spawns processes with `WmiPrvSE.exe` as the parent, detaching
them from the caller. Verified with Atomic Red Team "Create a Process using obfuscated
Win32_Process" (`10447c83-fc38-462a-a936-5102363b1c43`) run with
`process_to_execute=cmd.exe` (the default notepad.exe is absent in Windows Sandbox, so WMI
had nothing to spawn). Note: `wmic.exe` has been removed from current Windows 11, so the
detection targets the behavior (WMI-spawned interpreter), not the obsolete tool.

## Blind spots and assumptions
- A WMI-spawned binary that is not one of the listed interpreters won't match.
- Does not distinguish local from remote WMI; both surface as a WmiPrvSE parent.

## False positives
- Some management software launches scripts via WMI. Benign baseline: 0 hits; narrow by
  command line if that changes.

## Validation
- Fires on: `recordings/attack/T1047/10447c83-...evtx` (pending re-record with cmd.exe arg)
- Silent on: benign baseline. Enforced by `tests/test_detections.py`.

## Response
Correlate the spawned interpreter's command line and determine whether the WMI call was
local or remote (source host).
