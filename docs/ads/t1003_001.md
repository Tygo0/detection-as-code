# ADS: LSASS Memory Dump via comsvcs.dll (T1003.001)

## Goal
Detect credential theft by dumping LSASS process memory.

## Categorization
- ATT&CK: T1003.001 - OS Credential Dumping: LSASS Memory
- Tactic: Credential Access

## Strategy abstract
Watch process-creation telemetry (Sysmon EID 1) for `rundll32.exe` invoking the `MiniDump`
export of `comsvcs.dll` - a signed-binary way to dump LSASS without external tools.

## Technical context
`rundll32 comsvcs.dll MiniDump <pid> <file> full` writes an LSASS dump an attacker can
parse offline for credentials. Verified with Atomic Red Team "Dump LSASS.exe Memory using
comsvcs.dll" (`2536dee2-12fb-459a-8c37-971844fa73be`).

## Blind spots and assumptions
- Other dump methods (procdump, direct MiniDumpWriteDump, task manager) won't match this
  specific rule; each is its own detection.
- A stronger signal is Sysmon EID 10 (handle to lsass); add it if the config logs it.

## False positives
- Very rare; this exact comsvcs pattern is a well-known attack. Benign baseline: 0 hits.

## Validation
- Fires on: `recordings/attack/T1003.001/2536dee2-...evtx`
- Silent on: benign baseline. Enforced by `tests/test_detections.py`.

## Response
Treat as credential compromise. Isolate the host and rotate credentials that were resident
in LSASS.
