# ADS: Local Account Creation (T1136.001)

## Goal
Detect creation of a local user account, often used to establish persistent access.

## Categorization
- ATT&CK: T1136.001 - Create Account: Local Account
- Tactic: Persistence

## Strategy abstract
Watch process-creation telemetry (Sysmon EID 1) for the PowerShell `New-LocalUser` cmdlet
in the command line. (The authoritative signal is Security 4720; this rule uses the
process-creation path, which is what our Sysmon recording captures.)

## Technical context
`New-LocalUser` creates a local account; attackers add accounts for durable access.
Verified with Atomic Red Team "Create a new user in PowerShell"
(`bc8be0ac-475c-4fbf-9b1d-9fffd77afbde`).

## Blind spots and assumptions
- Account creation via `net user`, the Users MMC, or direct API won't match this rule
  (companion rules / Security 4720 would cover those).
- Relies on PowerShell command-line logging being present (Sysmon EID 1).

## False positives
- Legitimate admin provisioning. Measured against the benign baseline (0 hits).

## Validation
- Fires on: `recordings/attack/T1136.001/bc8be0ac-...evtx`
- Silent on: benign baseline. Enforced by `tests/test_detections.py`.

## Response
Confirm the account, who created it, and its group membership; disable/remove if rogue.
